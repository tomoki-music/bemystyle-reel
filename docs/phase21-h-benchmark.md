## 2. ワークフロー ステップ分析（コード検証）

### Step 1: 入力（simpleStep=1）
```
テンプレート選択 → フォーム入力 → 「AI自動作成」クリック
```
- テンプレートは前回選択が localStorage で保持される（`bemystyle-reel-simple-template-type`）
- MMMプリセットは前回保存値を自動ロード可能（Phase19-H）
- 前回画像キャッシュがあれば「前回の画像を使う」トグルが表示される

### Step 2: 確認（simpleStep=2）
```
内容確認 → 「AI自動作成を開始」クリック
```
- 再利用モード時は「画像生成をスキップするため早く完成します」が表示される

### Step 3: 実行・完成（simpleStep=3）
```
Factory実行（7ステップ）→ Rendering → 完成画面
```
- Phase21-C: 完成時に詳細機能を非表示、動画+DLボタンのみ表示
- 「詳細機能を表示」クリックで従来機能にアクセス可能

## 8. まだ残るボトルネック

### 優先度 高
1. **AI画像生成時間（〜12分）** — ユーザーが最も長く待つ箇所。改善案：
   - 画像枚数を14枚 → 7枚に削減（奇数スライドをループ）
   - 並列生成（現在は直列）
   - 節約モード（5枚）のデフォルト化

2. **再利用トグルの発見しにくさ** — 初回は表示されない → ユーザーが仕組みを知らない可能性。
   - 初回完成時に「次回は再利用できます」という通知を出す

### 優先度 中
3. **Step2 の存在意義** — 「AI自動作成」→「AI自動作成を開始」の2クリックは冗長に感じる。
   - Step2 をなくして Step1 から直接実行できるオプションも検討

4. **Rendering 時間（〜2分）** — 全パターン共通。短縮には Remotion のスペック調整が必要。

## 9. 次フェーズ提案

### Phase21-I: 並列画像生成（最大の時間短縮）
- 現在直列の API コールを Promise.all で並列化
- 14枚 × 50sec 直列 → 4〜6枚並列で **約60〜70% 短縮**（14分 → 4〜5分）
- API レート制限考慮で 3〜4 並列が現実的

### Phase21-J: 初回完成時「次回再利用できます」通知
- 初回AI生成完了後、キャッシュ保存完了と同時に通知を表示
- 「次回は画像生成をスキップできます（約4分早く完成します）」
- 再利用機能の発見率を上げる

### Phase21-K: Step2 スキップオプション
- 確認画面を省略して Step1 → 直接実行ボタンを追加
- 「確認なしで作成」ボタンで2クリック削減
